# NASA-modeling 外部数据需求表

> 本文依据 [`NASA-modeling.md`](NASA-modeling.md) 整理模型求解前需要从模型外部取得的数据。表中只列原始输入、规则、阈值和经营数据；由这些输入计算出的 `GDD`、`e(k)`、`ET0`、`ETc`、`TAW`、`RAW`、`q_{fkt}`、`chi_{fk}`、风险/健康评分、候选方案集合及目标尺度等属于预处理结果，不是外部数据。

## NASA API 分类

- **A：可由 NASA 科学数据 API 直接取值**：请求可直接返回 JSON/CSV 等科学数值，主要是 NASA POWER。
- **B：可由 API 检索，科学数据通常以文件获取**：CMR Search API 可检索 collection/granule 和下载地址；实际数据通常通过 Earthdata Login 后的 HTTPS、云对象、OPeNDAP 或 Harmony（具体能力依产品/DAAC 而定）获取。CMR 返回的是元数据，不能当成科学变量值。
- **C：NASA 有数据，但不建议作为该参数的直接来源**：只能提供代理、背景或校验，不能替代田块实测、农艺规则或经营事实。
- **不适用**：该数据不由 NASA 提供，应由农户、专家、供应商、市场、地方机构或其他公共数据源提供。

## 获取优先级

1. **先补齐不可替代的本地数据**：田块边界、规划期、作物/品种参数、土壤水力参数、基准轮作、农户偏好和供水/设备/种子/市场约束。
2. **NASA API 直接取数**：用 POWER API 获取温度、湿度/露点、风、气压和辐射，形成 GDD、ET0 与热冷风险的气象侧输入。
3. **NASA API 检索 + 文件下载**：用 CMR 查找 IMERG、SMAP、一个 DEM、HLS/MODIS、ECOSTRESS 和可选的 GRACE Mascon；保存 collection、granule、版本和下载 URL。
4. **本地校准优先于增加遥感产品**：雨量计、气象站、土壤检测和水分传感器对 `P_eff`、FC/WP、初始亏缺和阈值的价值高于堆叠多个重叠卫星产品。

## 结论

NASA 可覆盖的主要是**气象、降水、区域土壤水分、地形、植被/裸地、地表温度/ET 和长期总水储量背景**。其中只有 NASA POWER 属于本模型场景下明确的“API 直接返回科学数值”；多数 Earthdata 产品属于“API 检索 granule，随后下载科学数据文件”。NASA 无法提供完整模型不可替代的田块权属/边界、作物生理和轮作规则、土壤田间参数、价格成本、设备、种子、市场、灌溉供水事实和决策者偏好。

因此，NASA 数据是环境侧输入和证据层，而不是完整 MILP 输入。只有将 NASA 数据与本地农艺、田间、经营和偏好数据合并，并完成单位、尺度、QA、参数估计和候选方案生成后，才能把确定性参数提交给 Gurobi 求解。
