# Field Shift daily planner / 逐日轮作规划
Version: rotation-product-help-20261114-v1; model: rotation-milp-v3.0. Product documentation, not independent agronomic evidence. Availability depends on the running API, published data and current page state. Source specifications are docs/NASA-modeling.md and docs/NASA-modeling-external-data-requirements.md at main commit 8c498cf; implementation conventions are in docs/integration/model-v3-data-contract.md and model-v3-core.md. Older calculations retain their original model and help version.

农户从 /fields 绘制或导入农场，检查分割，确认地块边界，再补齐基本资料和历史并保存。边界确认不等于资料已同步，已同步也不等于足以计算。匿名草稿保存在本机，登录后须明确选择导入自己的账号；切换账号不得继承另一人的地块。地图中的临时提问选区只用于查询，不能改写农场或经营地块边界。已发布 NASA 图层是可视化，不能自动成为地块测量或经营资料。The map layer date, scientific observation window and future planning horizon are distinct.

# Preparing and checking / 准备与检查
在“轮作规划”选择当前分割中已同步的地块。一次最多选择十个地块；超过限制需明确分批，不能静默丢弃地块。分批后的共享资源额度需单独核对。依次核对规划日期、允许的作物、播期、资料来源、田间条件、共享资源和原定种法，点击“检查资料”，只有当前草稿检查通过才可“生成轮作方案”。修改草稿或保存新版历史后，之前的 readiness 失效，需要重新核对版本并检查。采用新版地块会撤销前茬与经营条件的确认；没有灌溉设施的地块不得保留供水关联。

必需值包括有效土层深度、FC/WP、pH、盐度、排水、坡度坡向及地形、历史和经营确认、水源、作业设备、分期种源和市场容量。每项保留值、单位、来源、地区、观测或适用时间、质量与确认状态。未知留空并注明原因，不能默认为零、无限容量或此前未种植。NASA 不能替代土壤检测、作物品种参数、种植历史、价格、供水权、农机和销售台账。工程假设必须明确标记并单独接受，不代表真实农户已经提供这些数据。

# History and baseline / 历史与原定种法
地块前茬可用年、月或日精度保存；未知具体收获日时保留原精度，以最晚可能结束日作为保守间隔核验边界。新增或修正后先“保存前茬记录”或“放弃前茬修改”。系统核对所有相关同科候选对，包括中间隔了另一作物的组合；也核对前茬和相邻作物规则。换茬占用期结束后才可播下一茬。

原定种法是农户明确确认的种植序列，每块地需有基准候选。它独立计算和校验，可能不满足硬条件或有经营缺口；不能把优化后的方案复制成基准。Benchmark 是工程参数包，baseline 是原定种法，二者不同。作物通过积温成熟并不代表土壤、地形、气候或设备条件都适宜。

# Daily water and maturity / 逐日水分与成熟
逐日模型使用版本化 GDD 配方和配套的品种成熟阈值；不能拿旧配方的阈值套入新配方。当前工程参数采用文档所列单侧温度截断，累计首次达到成熟阈值时得到模型收获日。生长日起止均计入；换茬期另算占用，不能全部当成有作物覆盖。

净灌溉估计依据 FAO-56 参考蒸散、阶段 Kc、有效雨量、随生长变化的根深和根区储水。FC/WP 与根深决定 TAW，耗水阈值决定 RAW。每日按亏缺、蒸散和有效雨量更新水量，计算维持该阈值所需的最小净补水。面积 ha 乘水深 mm 再乘十，换算为 m³。水源若提供毛供水量，必须有来源明确的灌溉效率，转换为净根区供水量且只转换一次。

当前独立候选初始水分政策为每个候选从萎蔫点开始，根区扩展的新增土层也按萎蔫点处理。这是公开的保守工程假设，可能高估灌溉；没有实现前后茬连续土壤水量衔接，也没有把 SMAP 表层含水量直接当成根区初始值。结果不是实测灌溉量或田间浇水指令。

# Six raw metrics / 六项原始指标
收益估计（profit，USD）来自参数化产量乘价格减生产成本，可为负数；它不是独立产量预测、实际净利润或收益承诺。价格、产量与成本都需来源和当地校准。净灌溉量（water，m³）是根区需求估计，不是水表记录。轮作衔接（rotation，score）表示相邻茬关系评分；土壤贡献（soil，score·ha）是面积加权代理评分，不是测得的土壤健康。气象与灌溉暴露（risk，score·ha）是高温、霜冻、过量雨及灌溉依赖的代理分数，不是损失概率。裸地面积天数（bare，ha-days）表示面积加权的无覆盖时段。

收益、衔接、土壤或风险等允许关闭的可选目标必须记录原因并将权重置零；未计算指标显示为空，不能解释成零收益或零风险。水和裸地等必需指标不能为了通过检查随意关闭。不同单位通过固定正尺度归一化，权重仅表达偏好；综合分数不能换算成产量、收入或实测土壤改善。

# Resource gaps and priorities / 资源缺口与优先级
求解首先最小化可补救的经营资源缺口成本，再优化六项指标的归一化综合分数。逐日水源与同类共享农机、分期种子采购与市场容量、裸地约束分别核验；禁止作物和不可补救的条件仍是硬约束。设备作业量发生在实际播种、收获等作业日。

有正缺口的结果是“需补救的诊断方案”，显示日期或期间、需求、容量、缺口、单位、缺口成本、补救条件和来源。比如外包设备须按登记的补救条件另行确认；求解最优不等于已经预约或具备实施条件。缺口成本独立于作物收益估计，不应把它误认为已支付的支出。没有资源缺口也只表示在这份输入下满足模型条件，工程参数、当地适宜性和实际资源仍需核对。详细缺口过多时聊天只展开明确注明的一部分，完整结果和导出保留全部条目。

# Alternatives and comparison / 备选与比较
同次计算可按不同偏好生成多个不同方案，也可能只有一个；缺少备选会说明原因，不为凑数编造。界面展示各自的原始指标、实际权重与尺度。权重或尺度不同时不能按综合分数直接排名。仅在已经生成的候选方案中判断互不支配，不代表获得完整的帕累托前沿。

跨计算比较必须匹配模型版本、地块及版本、规划日期、参数包及校验值、天气依据。允许经营条件、权重和气象情景不同，页面和 bot 展示这些差异。差值按所选对照结果减当前结果，与创建时间先后无关；任一指标未计算时相应差值为空。没有实际灌溉水表和实施前后记录，任何计算差值都不是实际节水；重新计算也不会启用实测节水能力。

# Save, reopen and recover / 保存、恢复与重算
计算作为独立任务运行，可查看状态、取消或重试。超时有可行结果尚未证明最优；超时无结果、失败、取消和无可行解分别显示。无可行解只说明所生成候选无法同时满足条件；没有明确冲突诊断时不能猜具体原因，基准违反条件也只解释基准。

提交结果尚未确认时用“按原请求重试”恢复同一请求，不能用编辑后的草稿替换。任务失败、取消或超时无结果时，“重试原始条件”使用旧快照；改变输入需新检查并生成新计算。已选完成且校验通过的方案可填写名称和备注保存，有缺口时明确“保存诊断方案”。硬约束失败或未校验结果不能保存成可用计划。已存计划保持当时的地块、输入、参数、天气、结果及来源，后续编辑不会覆盖；可从计算与已存计划恢复、导出完整依据或打印摘要。

# Sources, region and assistant / 来源、地区与助手边界
尚未选择真实业务试点；Iowa 参数是工程基准，不能自动推广到其他地区。NASA POWER 历史逐日天气回放和温雨情景不是未来预报。UTC 历史日序列仅在明确接受的工程模式中作为地方日代理，真实地区须配置适合的农业日历和气象资料。原始数据缺测、单位错误、质量不合格或地区不适用会阻止相应计算，不由聊天补造。

助手只解释当前账号有权查看的数据、已校验计算与版本化资料。方案数值必须来自服务端绑定的事实，不能用 LLM 推算或改写。对“如果改条件会怎样”，引导农户改表单、检查并重算；聊天不能修改农场、提交求解、保存计划、执行代码或读取其他账号。未计算草稿没有新的方案指标；旧结果始终对应旧输入。GIBS 画面、科学观测、模型估计、农户确认值和工程假设必须保持来源区别。
