# NASA 科学数据集时空特征与数据类型分析

## 分析目标

为后续将多个数据来源归一化到一致的时间和空间范围，并开展全维度数据分析与建模，对 [`docs/NASA-datasets-and-APIs.md`](../../docs/NASA-datasets-and-APIs.md) 中的“科学数据集”逐项分析以下属性：

- 时间跨度范围
- 时间颗粒度
- 空间覆盖范围
- 空间颗粒度或有效空间分辨率
- 数据类型

## 关键核验说明

### GPM 时间范围

NASA CMR 集合元数据和实际 granule 清单均显示 V07 从 1998-01-01 开始。浏览器核验到的当前文件边界如下：

| 产品 | 最早 granule | 最新 granule（核验时） |
|---|---|---|
| Early 半小时 | 1998-01-01 00:00 UTC | 2026-11-08 22:30 UTC |
| Late 半小时 | 1998-01-01 00:00 UTC | 2026-11-08 12:30 UTC |
| Final 半小时 | 1998-01-01 00:00 UTC | 2025-09-30 23:30 UTC |
| Final 逐日 | 1998-01-01 | 2025-09-30 |
| Final 月度 | 1998-01 | 2025-09 |

部分 IMERG 产品说明正文仍出现“自 2000 年开始”的概括，因此生产流程不应只依赖描述文字，应以 CMR granule 清单确定实际可下载日期，并对早期数据做完整性检查。

### DEM 时间含义

SRTM、NASADEM 和 ASTER GDEM 的日期是源雷达或影像的采集时期，不是重复观测周期。它们在时序模型中应作为静态或缓慢变化的地形协变量，不能当作对应采集日期的动态特征。

### GRACE 空间分辨率

GRACE 和 GRACE-FO Level-2 产品存储的是全球球谐系数，没有常规遥感栅格意义上的原生像元。将其转换为等效水厚时，空间分辨率取决于球谐截断、去条带和平滑方法，通常只有数百公里的有效尺度。

JPL Mascon 虽然可在约 0.5°网格上分发，但其独立质量变化估计单元约为 3°。0.5°像元不是相互独立的观测，建模时应保留 mascon ID 或聚合到流域、行政区等区域单元。

## 统一分析建模建议

### 时间归一化

不建议把全部数据强制插值为单一时间频率。建议建立三层时间体系：

1. **日尺度动态层**：GPM、SMAP、POWER，以及由 ECOSTRESS、HLS、Landsat、MODIS 聚合得到的日尺度或滚动窗口特征。
2. **月尺度慢变量层**：GRACE、GRACE-FO 或 Mascon 总水储量异常，以及其他变量的月统计量。
3. **静态空间层**：SRTM、NASADEM 或 ASTER DEM 派生的高程、坡度、坡向、地形湿度指数和流域属性。

建议保留以下时间质量字段：

- `observation_time`
- `window_start` / `window_end`
- `days_since_observation`
- `valid_observation_count`
- `cloud_fraction`
- `is_interpolated`
- `product_latency` 或产品运行阶段

ECOSTRESS、HLS 和 Landsat 存在云遮挡和不规则过境，不能无条件线性插值。更稳妥的方式是使用固定回看窗口的最近有效值、均值、中位数、极值和有效像元比例。

### 空间归一化

建议第一版地表动态分析立方体采用 **0.1°公共网格**：

- GPM 可直接对齐。
- SMAP、MODIS 和 POWER 按面积权重或保守重采样聚合。
- HLS、Landsat 和 ECOSTRESS 先执行质量筛选，再以有效像元统计量聚合。
- 分类或质量标识使用众数、比例或位标识统计，不能使用双线性插值。
- 连续状态量可使用面积加权均值；降水累计量需要使用守恒型重采样。

不应把 GRACE/Mascon 伪插值成 0.1°独立信息。应在 mascon 或流域尺度生成月度区域特征，再通过区域 ID 连接到细网格样本。

### 产品去重和版本管理

- GPM Early、Late、Final 是同一降水过程的不同处理阶段，不应同时作为三个相互独立的预测特征。实时模型使用 Early/Late，历史训练和评估优先使用 Final。
- Landsat 与 `HLSL30` 高度重叠。反射率建模优先使用已完成共网格、BRDF 和波段协调的 HLS；只有需要原始 Landsat 场景属性或地表温度时，再独立引入 Landsat Level-2。
- SRTM 与 NASADEM 来源高度相关。通常选择 NASADEM 作为 SRTM 重处理版本，并使用 ASTER GDEM 进行覆盖补充或交叉验证，不宜把三套高程当作三个独立环境驱动变量。
- 数据表中必须保存 `product_short_name`、`version`、`processing_run`、`source_granule_id` 和处理日期，以避免版本更新后无法复现。

### 建议的共同分析时段

若模型同时依赖 ECOSTRESS、HLS、GRACE-FO 和其他长期动态数据，共同分析起点约为 **2018-07-09**。按核验时可用的 GPM Final 数据，历史一致性分析可暂定为：

> **2018-07-09 至 2025-09-30**

实际建模还需根据研究区域内 ECOSTRESS/HLS/Landsat 的有效观测、云量和 GRACE 缺月情况生成时间可用性矩阵。DEM 是静态特征，不限制共同时间窗口。
